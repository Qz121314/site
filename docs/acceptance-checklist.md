# 发布验收清单

这份清单用于每次发布候选版本的人工关键路径验收。CI 会在部署后使用真实 Chromium 自动检查 Storefront、后台登录边界、动态 PWA 图标、Messages 空状态和 CTA 可见性；本清单继续负责会修改真实业务数据的交互、R2 / D1 和回退演练。

## 验收前提

- 使用非生产测试内容，避免覆盖正在运营的数据；
- 确认 `ADMIN_PASSWORD` 与 `SESSION_SECRET` 已使用 Worker Secret 配置且不是空值；
- 确认 D1 增量迁移已全部应用；
- 确认 R2 自定义域名与 `media_base_url` 一致；
- 记录验收 commit、Worker 版本和开始时间。

## 1. 认证与会话

- [ ] `/admin/` 未登录时显示登录页；
- [ ] 错误密码返回明确错误，不创建会话 Cookie；
- [ ] 连续错误达到阈值后返回 429 和 `Retry-After`；
- [ ] 正确密码登录后 Cookie 包含 `HttpOnly`、`Secure`、`SameSite=Strict`；
- [ ] 刷新 Admin 后会话仍有效；
- [ ] 退出后受保护 API 返回 401；
- [ ] 会话过期后 Admin 统一回到登录页。

## 2. 内容录入关键路径

按顺序创建一组带唯一前缀的测试数据：

```text
分区
→ 分类与标签
→ 素材上传
→ 转化分组与入口
→ 产品草稿
→ 产品发布状态
→ FAQ
```

- [ ] 所有列表能搜索到新数据；
- [ ] 跨分区分类、标签、转化分组不能误绑定；
- [ ] 产品封面和图集能从素材中心选择并正确排序；
- [ ] 关闭有修改的 Dialog、切换菜单、刷新和退出登录都会提示未保存；
- [ ] 保存完成后未保存提示消失；
- [ ] 保存失败时，错误显示在仍打开的编辑 Dialog 内，修改字段后旧错误消失；
- [ ] 主题、站点设置、素材和发布状态读取失败时提供明确的重试入口；
- [ ] 退出失败时在后台界面显示错误，不使用浏览器原生弹窗；
- [ ] 任意业务管理 API 返回 401 后，Admin 统一回到登录页；
- [ ] 删除有依赖的数据会被阻止并显示原因；
- [ ] 回收站恢复后业务引用仍完整。

## 3. 发布与 Storefront

- [ ] 后台正确显示变脏模块；
- [ ] 发布单个分区后只更新对应模块版本；
- [ ] 发布站点、导航和 FAQ 后生成新的不可变 R2 JSON；
- [ ] `/public/current.json` 指向新的组合版本；
- [ ] 所有发布 JSON 都从当前站点同源 `/public/*` 读取，不使用媒体自定义域名；
- [ ] Storefront 首页、分区页和产品详情显示刚发布的数据；
- [ ] 手机宽度保持双列产品卡、可触控筛选和 Safe Area 底部导航；
- [ ] Browse 使用直切的编辑式分区入口；卡片、搜索框和贴底导航没有恢复成大圆角胶囊；
- [ ] Home 分区快捷图标和 More 图标保持统一的 12px 圆角方形，与直切内容卡片形成明确层级；
- [ ] 图片 / GIF / 视频正常显示，失效媒体显示稳定占位；
- [ ] 阻断 R2 Custom Domain 后，已登记图片和视频通过 `/_media/*` 同源路径重试成功，视频 Range 请求返回 206；
- [ ] 将 R2 自定义域名切换到同一 Bucket 的另一个已验证域名后，不重新构建前端也能读取公开内容和媒体；
- [ ] CTA 使用当前 D1 转化配置并正确跳转；
- [ ] 所有 CTA 都经过 `/go/{productId}`；链接模式按当前转化池轮换，在线客服模式生成唯一 `handoffId` 并进入 Messages；
- [ ] Site 不恢复流量统计页面、`/api/admin/traffic` 或 CTA `conversion_events` 运行时写入；`handoffId` 只用于客服接待链路关联。

## 4. Rollback

- [ ] 选择刚发布模块的上一版本执行 Rollback；
- [ ] 只有目标模块的 current pointer 发生变化；
- [ ] Storefront 恢复上一版本内容；
- [ ] 重新发布当前 D1 内容后可回到最新版本；
- [ ] 当前版本和保留版本引用的素材不会进入物理清理。

## 5. 生产冒烟证据

- [ ] `/api/health` 返回 production、Worker Version ID 和 request ID；
- [ ] `/api/public/theme` 与 `/public/current.json` 返回正确 JSON 和缓存头；
- [ ] `/`、`/admin/`、分区深链和产品深链返回 SPA；
- [ ] 响应包含 CSP、`X-Content-Type-Options`、`X-Frame-Options` 和 `Referrer-Policy`；
- [ ] GitHub Actions 的 validate、deploy 和 smoke steps 全部通过；
- [ ] 记录验收人、结束时间、失败项和修复链接。

## 6. 自动化浏览器收口门禁

主分支部署只有通过以下真实生产地址检查后才算完成：

- Storefront 首页和 Browse 路由成功渲染，底部导航可见且无页面运行时异常；
- Browse 分区卡、搜索入口和移动底栏保持 0px 外轮廓圆角，避免视觉系统退回通用圆角卡片；
- Home 快捷图标保持 12px 圆角，图标类元素不被内容卡片的直切规则误伤；
- Manifest 返回后台品牌信息，192 / 512 图标均为可读取的 PNG；
- 后台登录页保留密码认证边界；
- Messages 的导航显示只受后台显示开关控制；没有客服连接时页面显示明确状态；
- 已发布产品即使没有配置转化目标，也始终保留 CTA 按钮外观。

这组检查位于 `tests/e2e/production-smoke.spec.ts`，由主分支部署任务自动执行；失败会直接将该次部署工作流标记为失败。
