# R2 图片管理

后台素材库本质上是 `service-catalog-site-assets` 的图片管理界面，不提供上传功能。

```text
扫描整个 R2 Bucket
→ 识别全部图片对象
→ 根据 D1 业务引用分为使用中 / 未使用
→ 未使用图片可选择、全选和批量物理删除
```

## 扫描范围

系统不限制对象 Key 前缀。无论图片存放在根目录或任何前缀下，只要满足以下任一条件就进入图片列表：

- R2 HTTP metadata 的 `Content-Type` 以 `image/` 开头；
- 对象 Key 使用已支持的图片扩展名。

非图片对象不会显示在素材库中，也不能通过素材库清理。

扫描通过 Worker 的 `ASSETS_BUCKET.list()` 完成：

- 每次最多读取 500 个 R2 对象；
- 使用 R2 返回的 `truncated` 和 `cursor` 自动扫描下一页；
- React 页面会自动扫描到 Bucket 列表结束；
- 不要求管理员手动点击“继续扫描”；
- 同时读取 HTTP metadata 判断图片类型；
- 最终统计代表本次扫描发现的全部图片。

## 使用状态

每张图片只分为两个状态：

```text
使用中
未使用
```

使用中表示该图片在 D1 中至少存在一个业务引用：

```text
site_settings.logo_asset_id
sections.icon_asset_id
products.cover_asset_id
product_media.media_asset_id
```

软删除数据仍然算作引用，避免图片被物理删除后无法恢复对应产品或分区。

未使用包括：

- 已登记在 `media_assets` 但当前无业务引用的图片；
- R2 中存在、但没有 `media_assets` 记录的图片。

这些数据库差异属于后台内部对账信息，不作为运营页面的额外分类。

## 物理清理

管理员只能选择“未使用”图片。清理流程为：

```text
选择未使用图片
→ 提交幂等批量请求
→ 再次读取 R2 对象 metadata
→ 再次查询 D1 引用
→ 锁定对应 media_assets 状态
→ 调用 R2 delete 物理删除对象
→ 写入完成审计和幂等响应
```

删除成功后，R2 中不再存在该对象，操作不可恢复。

如果提交时图片已经被 Logo、分区或产品引用，整批清理停止并要求重新扫描。不会根据页面中的旧状态盲目删除。

R2 删除失败时：

```text
恢复 media_assets 原状态
→ 写入失败审计
→ 返回明确错误
```

## 批量限制

后台每次最多物理删除 100 张图片。该限制用于控制误操作范围、审计数据大小和 Worker 请求执行时间。

## 页面结构

```text
全部图片数量
使用中数量
未使用数量
图片总容量

使用中 Tab
未使用 Tab
```

只有“未使用”Tab 中的图片可以勾选。支持搜索、当前结果全选和批量物理清理。

## 明确禁止

- 素材库提供上传按钮；
- 把图片分成复杂的技术状态供运营人员判断；
- 允许删除使用中的图片；
- 仅凭前端扫描结果执行删除；
- 绕过最终 D1 引用检查；
- 自动清空整个 Bucket；
- 删除非图片对象。
