# R2 素材库管理

素材库不是上传模块。它只负责扫描 `service-catalog-site-assets` 中的图片对象、核对 D1 引用并清理确定未使用的对象。

## 扫描范围

```text
扫描：media/
忽略：public/
忽略：其他系统前缀
```

R2 使用扁平对象 Key。所谓目录只是 Key 前缀，因此服务端必须固定使用 `media/` prefix，不允许后台传入任意扫描路径。

扫描通过 Worker 的 `ASSETS_BUCKET.list()` 完成：

- 每页最多读取 100 个对象；
- 使用 R2 返回的 `truncated` 和 `cursor` 继续扫描；
- 不根据当前页对象数量判断是否扫描结束；
- 同时读取 HTTP metadata，用于判断 Content-Type；
- 前端显示的是“已加载容量”，不是整个 Bucket 的估算总量。

## 引用检测

每个 `media_assets.object_key` 会核对以下引用：

```text
site_settings.logo_asset_id
sections.icon_asset_id
products.cover_asset_id
product_media.media_asset_id
```

软删除记录仍然算作有效引用，因为分区和产品可能从回收站恢复。只有所有引用都不存在时，图片才可能进入清理候选。

扫描结果分为：

```text
D1 已登记 / R2 未登记
正在使用 / 无引用
可清理 / 正在使用 / 24 小时保护 / 非图片对象
```

## 清理资格

对象必须同时满足：

1. Key 位于 `media/`；
2. Content-Type 或文件扩展名可识别为图片；
3. D1 引用数量为 0；
4. 对象上传时间超过 24 小时。

24 小时保护期用于避免删除仍处于产品录入、对象确认或失败重试流程中的新图片。

## 删除流程

```text
管理员选择候选对象
→ 提交幂等批量请求
→ 再次读取 R2 metadata
→ 再次查询 D1 引用
→ 乐观锁定对应 media_assets 记录
→ 永久删除 R2 对象
→ 写入完成审计和幂等响应
```

并发期间引用或媒体记录发生变化时，整批停止并要求重新扫描，不进行部分删除。

R2 删除失败时：

```text
恢复 media_assets 原状态
→ 写入失败审计
→ 返回明确错误
```

R2 已删除但最终 D1 记录失败时，同一幂等请求可以重新提交；缺失对象会被视为已经删除并完成元数据对账。

## 批量限制

后台每次最多选择 100 个对象。Cloudflare Workers R2 API 支持单次删除最多 1000 个 Key，但项目主动使用更小批次，以限制误操作范围、审计数据大小和请求执行时间。

## 明确禁止

- 素材库提供上传按钮；
- 扫描或删除 `public/` 发布文件；
- 删除仍被软删除产品或分区引用的图片；
- 仅凭 D1 状态删除对象；
- 仅凭前端扫描结果删除对象；
- 绕过最终引用检查；
- 自动清空整个 Bucket。
