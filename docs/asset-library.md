# R2 素材中心

后台素材中心管理 `service-catalog-site-assets` 中的图片、GIF 和视频。它同时负责上传、目录整理、业务引用识别和未使用对象清理。

## 支持范围

| 类型             | 上传与展示策略                                                          |
| ---------------- | ----------------------------------------------------------------------- |
| JPG / PNG / WebP | 浏览器优化为 WebP，失败时回退 JPEG；服务端校验 MIME、文件头、尺寸和大小 |
| GIF              | 保留动画原文件；服务端按 GIF 契约校验                                   |
| MP4 / WebM       | 作为结构化视频素材保存，由 Storefront `<video>` 展示                    |

素材中心支持：

- 上传队列、并发进度、失败重试和重复内容复用；
- 文件夹新增、重命名、删除和批量移动；
- 搜索、类型 / 用途 / 状态筛选和 Cursor 分页；
- 素材选择器与站点 Logo、分区图标、产品封面 / 图集复用；
- 使用中、未使用和回收状态；
- 批量删除与 R2 物理清理。

## 数据与对象关系

```text
浏览器选择文件
→ 客户端图片优化（适用时）
→ Worker 校验内容
→ R2 写入对象
→ media_assets 保存元数据
→ 业务表保存 media_asset_id 引用
```

业务引用包括：

```text
site_settings.logo_asset_id
sections.icon_asset_id
products.cover_asset_id
product_media.media_asset_id
```

软删除业务记录仍视为引用，避免恢复分区或产品后素材已经被物理删除。当前保留的发布快照也会形成清理保护。

## 上传规则

- 素材文件通过 Worker 的 R2 Binding 写入，不从 Worker 调用 Cloudflare REST API；
- 对象 Key、公开 URL 和 `media_assets` 元数据由服务端统一生成；
- 相同内容按哈希复用，避免重复占用 R2；
- 上传队列为 single-flight 调度，避免重试与新任务互相超额占用并发槽；
- GIF / 视频不会进入静态图片压缩流程；
- 任意 HTML 不得用于注入视频或脚本。

## 删除与清理

删除采用两层保护：

```text
页面选择素材
→ 提交幂等请求
→ 服务端重新查询 D1 引用与快照保护
→ 仅允许处理未使用对象
→ 删除 R2 对象
→ 更新 D1 状态并写入审计
```

存储清理页首次进入只扫描首个 Cursor 批次（最多 500 个对象）。继续扫描下一批或扫描全部必须由管理员显式触发，避免仅打开清理页就产生连续 Worker 请求。全量扫描完成前，页面统计和清理列表只代表当前已扫描范围。

禁止：

- 删除仍被当前或软删除业务记录引用的素材；
- 仅根据前端旧状态执行物理删除；
- 绕过发布快照保护；
- 自动清空整个 Bucket；
- 通过素材清理接口删除非媒体对象；
- 使用本地原图临时路径作为正式产品数据。

## 公开读取

Admin 写入使用 `ASSETS_BUCKET` Binding。Storefront 图片、GIF 和视频读取使用站点设置中的 R2 自定义域名；若媒体域名或 CORS 暂时不可用，已登记媒体可通过 Worker 同源 `/_media/*` 重试。发布 JSON 始终通过 Worker 同源 `/public/*` 读取。

生产部署会解析并验证 R2 自定义域名、写入公开 CORS；只有存在 ready 媒体时才用真实媒体对象探测直接读取，并在 Worker 部署后再次冒烟检查。
