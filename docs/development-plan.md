# 开发阶段与交付计划

本文档定义业务运营平台的实施顺序。最终平台由两个项目组成：

```text
Qz121314/site
用户前端 + 商家后台 + 业务 API

Qz121314/support-platform
独立实时客服平台
```

当前只建设 `Qz121314/site`。客服平台在业务运营平台的数据模型、产品路由和集成协议稳定后单独创建。

## 1. 开发原则

- 先完成数据库和后台数据录入，再开发用户前端；
- Storefront 与 Admin 保留在同一个仓库，但分别构建；
- 本仓库只部署一个正式 Worker；
- PR 只校验，不创建 Preview Worker；
- 公开内容使用版本化快照；
- 客服平台通过标准 HTTPS、WebSocket 和 Webhook 对接；
- 不使用 Service Bindings 作为必需依赖；
- 两个项目不共用数据库；
- 所有跨系统接口必须版本化、鉴权并支持幂等。

## 3. 阶段 1：主业务数据库和权限

目标：先建立商家后台的数据核心。

任务：

- [ ] 建立 merchants、admin_users、roles 和 permissions；
- [ ] 建立 merchant_id 数据隔离；
- [ ] 建立管理员会话和 RBAC；
- [ ] 建立 Channel、Category、Tag、Store、Listing 领域模型；
- [ ] 建立 English / Español 翻译表；
- [ ] 建立内容状态和发布状态；
- [ ] 建立审计日志；
- [ ] 建立软删除、恢复和回收站；
- [ ] 建立批量操作和幂等机制；
- [ ] 为常用查询和外键建立索引；
- [ ] 建立迁移、种子和备份恢复脚本。

完成标准：

- 商家和管理员可以安全登录；
- 数据按商家严格隔离；
- 最小 CRUD API 可运行；
- 所有写操作可审计；
- 删除支持恢复和批量处理。

## 4. 阶段 2：中文商家后台数据录入

目标：让商家可以完整管理业务数据。

任务：

- [ ] 仪表盘基础状态；
- [ ] 频道、分类和标签管理；
- [ ] 地区和门店管理；
- [ ] Listing 管理；
- [ ] English / Español 翻译编辑；
- [ ] 草稿、审核、批准、发布和归档；
- [ ] 统一列表、分页、筛选和字段选择；
- [ ] 行选择、当前页全选和批量删除；
- [ ] 转化池和广告池批量操作；
- [ ] 回收站和恢复；
- [ ] 操作日志和危险操作确认。

所有涉及删除的页面必须统一支持：

```text
选择
当前页全选
批量删除
删除确认
软删除
恢复
审计
```

完成标准：

- 核心业务数据可以完整录入、编辑、删除和恢复；
- 管理后台不依赖 Storefront 才能验证业务逻辑；
- 批量操作具备权限、数量限制和事务策略。

## 5. 阶段 3：媒体系统

目标：完成产品、门店和广告媒体闭环。

任务：

- [ ] 建立上传预约接口；
- [ ] 分配受控对象 Key；
- [ ] 客户端压缩和上传；
- [ ] 服务端确认对象存在；
- [ ] 校验 MIME、扩展名、大小和尺寸；
- [ ] 移除 EXIF 和定位信息；
- [ ] 建立 `media_assets` 和引用关系；
- [ ] 实现封面优先、产品图第一张回退；
- [ ] 实现内容哈希去重；
- [ ] 清理未确认和无引用对象；
- [ ] 统一卡片、详情、门店和 Banner 图片比例。

完成标准：

- 数据库只保存对象 Key；
- 图片尺寸规则可验证；
- 上传失败不会长期遗留垃圾对象；
- 产品列表不显示独立缩略图。

任务：

- [ ] 建立 publish_jobs；
- [ ] 建立发布锁和幂等键；
- [ ] 校验双语完整度；
- [ ] 生成版本化 JSON；
- [ ] 生成 manifest、哈希和字节数；
- [ ] 上传不可变版本目录；
- [ ] 验证全部输出；
- [ ] 最后切换 current.json；
- [ ] 建立失败恢复；
- [ ] 建立版本列表和回滚；
- [ ] 建立旧版本保留和清理。

- 回滚不需要重新生成内容；
- 数据库存储成功与公开发布成功明确区分。

- [ ] 移动端优先首页和导航；
- [ ] 地区、频道、分类和标签筛选；
- [ ] 分类下拉菜单；
- [ ] 标签筛选按钮；

- [ ] PC 默认一行两列；
- [ ] 移动端单列或紧凑双列；

- [ ] 产品咨询按钮；
- [ ] 加载、空状态、错误和离线状态；
- [ ] PWA 安装、更新和缓存隔离；

- Storefront Service Worker 不控制 `/admin` 和 `/api`；
- 用户无需普通账号即可浏览和发起咨询；
- 前端和后台仍由同一业务项目维护。

## 8. 阶段 6：客服平台集成层

目标：为独立实时客服平台建立稳定接口，而不是在本仓库内实现客服系统。

任务：

- [ ] 建立 `support_connections`；
- [ ] 支持 API 地址、WebSocket 地址、实例 ID 和租户 ID；
- [ ] 加密保存机器凭证和 Webhook Secret；
- [ ] 建立连接测试和能力发现；
- [ ] 建立客服分组只读同步；
- [ ] 建立 `external_support_groups` 只读缓存；
- [ ] 产品绑定外部客服组和备用组；
- [ ] 建立客服目录更新 Webhook；
- [ ] 建立手动刷新和周期核对；
- [ ] 建立 Mock 客服平台用于联调；
- [ ] 建立 OpenAPI 和 JSON Schema 契约。

后台只读取客服平台结果，不管理：

```text
客服账号
客服组成员
轮询顺序
最大接待数
在线状态
等待队列
实时消息
```

完成标准：

- 后台可以安全连接外部客服平台；
- 后台可以读取并选择外部客服分组；
- 产品不绑定具体客服；
- 客服平台不可用时不影响公开内容浏览。

## 9. 阶段 7：咨询与转化闭环

目标：让用户咨询和客服结果回传形成运营闭环。

任务：

- [ ] Storefront 向本项目 API 发起咨询；
- [ ] 服务端校验产品、商家和外部客服组；
- [ ] 服务端调用客服平台创建会话；
- [ ] 返回短期会话令牌和 WebSocket 地址；
- [ ] 用户聊天界面连接客服平台；
- [ ] 接收签名 Webhook；
- [ ] 按 eventId 幂等处理；
- [ ] 更新转化池和广告池；
- [ ] 展示产品、门店和来源统计；
- [ ] 建立失败重试、告警和审计。

完成标准：

```text
商家录入
→ Storefront 展示
→ 用户点击咨询
→ 客服平台轮询分配
→ 实时图文聊天
→ 转化结果回传
→ 商家后台查看结果
```

## 10. 阶段 8：独立实时客服平台

当阶段 6 的协议稳定后，创建独立仓库：

```text
Qz121314/support-platform
```

客服平台负责：

- 客服管理后台；
- 客服工作台；
- 客服账号和分组；
- 组内轮询和并发安全分配；
- 等待队列和超时重分配；
- WebSocket 实时连接；
- 文本、图片和文件消息；
- 消息确认、已读和断线恢复；
- 会话转接、跟进和转化；
- 预签名 URL 文件直传；
- 向业务运营平台回传事件。

客服平台可以部署在不同 Cloudflare 账号、其他云或自购服务器。

## 11. 交付优先级

当前优先级固定为：

```text
P0  数据库和商家后台核心
P1  媒体和发布管线
P2  Storefront
P3  客服平台集成契约
P4  独立实时客服平台
```

在 P0 完成前，不提前实现复杂实时客服、AI、第三方 Provider 或无关装饰功能。
