# 开发阶段与交付计划

当前只建设 `Qz121314/site`。目标是先完成中文后台的数据录入和管理，再完成英文用户前端。

实时在线客服、多语言和独立客服接口不在当前开发范围。

## 1. 开发原则

- 先确定用户路径和 UI，再冻结数据结构；
- 前端只使用 English；
- 后台只使用中文操作界面；
- 所有公开内容由后台录入，不在源码中写死行业；
- 分区是后台动态业务菜单；
- 产品和转化方式在各自分区内部管理；
- Storefront 与 Admin 同仓库、分别构建；
- 本仓库只部署一个正式 Worker；
- PR 只校验，不部署长期 Preview Worker；
- 所有删除功能统一支持选择、全选、批量删除、软删除、恢复和审计。

## 4. 阶段 2：分区管理和动态后台菜单

目标：让管理员创建业务分区，并自动生成后台业务菜单。

分区录入字段固定为：

```text
分区名称
分区图标
排序
是否启用
```

任务：

- [ ] 建立 `sections` 表；
- [ ] 建立分区新增、编辑、列表和详情 API；
- [ ] 建立分区启用和停用；
- [ ] 建立分区排序；
- [ ] 建立分区软删除和恢复；
- [ ] 建立分区列表选择、全选和批量删除；
- [ ] 建立后台动态菜单加载接口；
- [ ] 创建分区后自动出现业务菜单；
- [ ] 分区菜单内固定显示“产品管理”和“转化方式”；
- [ ] 停用分区不进入公开发布和默认动态菜单；
- [ ] 删除分区前检查关联数据。

完成标准：

```text
新增分区
→ 动态后台菜单出现
→ 前端发布数据包含该分区
```

后台无需修改代码即可增加新的业务。
