# 优化与交付计划

本项目的既定业务范围已经完成。后续工作以验收、稳定性、可维护性和生产运行质量为主，不继续堆叠新业务模块。

## 产品边界

项目服务个人运营者和小团队，保持一套 Storefront、一套中文 Admin、一个 Cloudflare Worker、一个 D1 数据库和一个 R2 Bucket。

当前不增加：

- AI 管理或生成能力；
- 广告池或广告投放平台；
- 多管理员账号、组织、角色或 RBAC；
- 在本仓库内建设审批、工单、实时聊天或坐席系统；
- 六套相互独立的前端代码；
- 可执行第三方 JavaScript / React / 任意 CSS 主题。

## 当前基线

以下能力已经落地：

- 单管理员登录、签名会话、登录限流和写操作审计；
- 站点设置、主题中心、素材中心和客服连接配置；
- 分区、分类、标签、产品、FAQ 和转化池管理；
- R2 图片 / GIF / 视频上传、引用保护和未使用素材清理；
- 模块化发布、不可变内容版本、历史记录和 Rollback；
- English、Mobile-first Storefront；
- D1 增量迁移、CI 校验、Cloudflare 自动部署和生产冒烟测试。

## 推荐优化顺序

### P0：发布前必须完成

1. **关键路径验收**：按照 [发布验收清单](acceptance-checklist.md) 检查登录、内容录入、素材、发布、前台读取和回滚。
2. **认证回归**：自动覆盖配置缺失、无效请求、会话签名与过期、登录成功和连续失败限流。
3. **文档一致性**：README、架构、认证、素材和交付文档只描述当前实现。
4. **未保存保护**：所有 Admin Dialog 表单以及站点设置、主题中心和产品编辑器都必须进入统一的离开保护。
5. **生产验证**：CI 必须完成迁移、Lint、Typecheck、测试、构建、Worker dry-run、部署和线上冒烟。

### P1：稳定后继续

1. 前台优先使用可读 slug，同时兼容历史 ID 链接和已发布快照；
2. 收敛 Admin 重复样式和高优先级覆盖，保持现有信息架构；
3. 让主题预览尽量复用 Storefront 的真实组件和 Token；
4. 清理确认无调用方的旧上传、旧发布和未消费数据路径；
5. 为 D1 迁移补充 expand / contract 兼容规则和恢复手册。

## 每批交付标准

每批优化都必须满足：

```text
增量改动
→ D1 本地迁移验证
→ Lint / Typecheck / Test
→ Production Build
→ Worker dry-run
→ 合并 main
→ Cloudflare 部署
→ 生产冒烟
```

若某一步失败，该批次不能视为已完成。生产数据结构继续只通过编号迁移升级，不重建正式 D1。
