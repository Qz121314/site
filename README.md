# 业务展示与运营模板

本仓库 `Qz121314/site` 是一个完全由后台数据驱动的业务展示模板。

```text
Storefront   English 用户前端
Admin        中文管理后台
Worker       业务 API、认证、上传、发布和静态资源路由
D1           业务数据、状态、审计和发布记录
R2           图片 / GIF / 视频素材与不可变公开内容版本
```

模板不预设任何行业。分区、产品、转化方式、主题、素材、热门内容和 FAQ 全部由后台管理。

## 产品定位与设计原则

本项目面向个人运营者或小团队使用，不按大型企业后台的方向设计。

核心原则：

```text
简洁
高效
稳定
易维护
```

功能设计优先解决真实运营需求，不为了“功能完整”堆叠低频或用不到的模块。新增功能前应先判断是否能明显改善日常录入、内容管理、转化配置、发布或维护效率；如果收益不明确，默认不增加。

后台管理同样遵循这一原则：保持简单直接的登录和操作流程，不主动引入复杂账号体系、组织体系、审批流或细粒度 RBAC。只有未来出现明确的实际需求时才重新评估。

## 明确不在项目范围内

以下功能不是当前项目目标，也不应在常规优化中作为“缺失功能”补充：

```text
AI 管理 / AI 生成功能
广告池 / 广告投放管理
复杂管理员账号、角色与权限系统
为大型组织设计的审批与协作流程
```

后续开发和代码审计应以“个人 / 小团队、简洁高效、功能稳定”为基准，不以企业级后台的功能数量作为完成度标准。

## 当前核心能力

```text
D1 / R2 / R2 Custom Domain 数据基线
→ Worker 变量单管理员登录
→ 站点设置与媒体域名
→ 主题中心
→ 全站素材中心
→ 分区管理
→ 动态分区菜单
→ 分区内产品 / 分类 / 标签 / 转化方式管理
→ Markdown 正文
→ 热门推荐与 FAQ
→ 模块化发布与回退
→ English Storefront
```

实时客服和多语言不在当前范围。

## 主题中心

用户前端采用“一套业务组件 + 多套主题预设”的方式，不为不同赛道维护多套业务代码。

当前主题预设：

```text
Marketplace   通用业务目录 / 本地服务
Noir         成人内容 / 会员展示的深色视觉
Live         直播 / 娱乐入口
SaaS         软件 / 工具 / 企业服务
Travel       文旅 / 景区 / 本地体验
Tech         科技 / 硬件 / 创新产品
```

主题负责颜色、明暗模式、表面层级、阴影、Hero 氛围和其他展示 token；业务数据结构保持一致。

### 产品媒体比例

产品列表和产品封面统一以 **1:1 正方形** 作为跨主题视觉基准。这样在 PC 双列、移动端双列以及不同主题之间能保持稳定的卡片节奏。

1:1 不是全站媒体强制格式：

```text
产品列表封面      1:1
产品详情图片      保留内容合适比例
GIF              保留原始比例与动画
视频             保留源视频比例
Logo / 图标       按品牌和图标容器适配
Hero / Banner     使用主题和内容需要的横向比例
Markdown 正文图   保留原始比例并限制最大显示尺寸
```

主题中心允许在预设基础上覆盖品牌强调色，但不把后台变成复杂的网页设计器。

## 全站素材中心

素材中心不再只服务产品图片，而是作为全站统一媒体库。**产品录入不提供文件上传入口**：产品图片、GIF 和视频必须先进入素材中心，然后在产品录入中通过缩略图选择现有素材。

支持的技术类型：

```text
静态图片   JPG / PNG / WebP
动图       GIF
视频       MP4 / WebM
```

### R2 静态图片上传基线

**JPG / PNG / WebP 原图禁止直接上传到 R2。** 原始文件只存在于管理员浏览器本地，上传流程必须先在浏览器完成重绘、缩放和重新编码，再把优化后的文件提交给 Worker。

当前静态图片规则：

```text
本地 JPG / PNG / WebP
→ 浏览器读取原图
→ 最长边压缩到不超过 1200px
→ WebP 质量 0.82（浏览器不支持时回退 JPEG）
→ 只把压缩后的文件放入上传请求
→ Worker 校验压缩协议与输出格式
→ R2 只保存 optimized 文件
```

Worker 必须拒绝缺少受支持压缩标记的静态图片上传请求，不能只依赖后台 UI 约定。Logo 和分区图标的独立上传入口同样必须先经过浏览器压缩，并由 Worker 校验压缩协议。

GIF 为避免破坏动画帧、MP4 / WebM 为避免在后台浏览器内引入重型转码链路，当前保留其原有动画 / 视频编码，不使用静态图片 Canvas 压缩。若未来要求视频也统一转码，应使用独立的视频编码方案，而不是把原视频转码职责塞入普通素材上传表单。

上传时由系统自动识别技术类型，管理员选择素材用途：

```text
通用素材
产品素材
Logo
图标
Favicon
Banner / Hero
背景素材
正文素材
```

技术类型和素材用途是两个独立概念。例如 GIF 可以作为产品素材或正文素材；PNG 可以作为 Logo、图标、Hero 或通用素材。

### 素材文件夹

素材中心支持轻量的一层文件夹，用于把大量素材按项目、产品或批次整理。文件夹只是 D1 中的组织关系，不改变 R2 `object_key`，因此移动素材或重命名文件夹不会影响已经存在的产品引用和公开媒体链接。

支持两种上传方式：

```text
上传文件
→ 选择一个现有素材文件夹或“未分组”
→ 批量上传多个支持格式文件

上传文件夹
→ 选择本地文件夹
→ 使用本地顶层文件夹名称创建 / 复用素材文件夹
→ 将其中支持的素材统一上传到该分组
```

为了保持小团队操作简单，本项目不复制本地多级目录树；本地子目录中的支持文件会归入同一个顶层素材文件夹。删除素材文件夹也不会删除素材，文件只会回到“未分组”。素材可以批量移动到其他文件夹。

### 产品选择素材

产品录入中的媒体区域只负责：

```text
从素材中心选择
→ 先查看 1:1 缩略图预览
→ 按文件夹 / 图片 / GIF / 视频筛选
→ 搜索文件名
→ 最多选择 12 个产品媒体
→ 调整顺序
→ 选择图片或 GIF 作为封面
→ 从当前产品移除引用
```

产品录入移除素材只解除当前产品引用，不删除素材中心中的 R2 文件。视频不能作为产品封面。

素材记录只保存 R2 `object_key`，公开 URL 由当前媒体域名统一生成。压缩后的静态图片 / GIF 默认最大 20 MB，视频默认最大 60 MB。

日常素材管理与底层存储清理分开：

```text
素材中心
→ 上传、文件夹分组、筛选、缩略图预览、复用、全选、批量移动和批量删除

存储清理
→ 扫描 R2 历史图片对象
→ 检查业务引用和发布快照保护
→ 只物理清理确认安全的孤立对象
```

## Markdown 正文

产品正文和 FAQ 正文使用 Markdown。

当前安全渲染支持标题、段落、列表、引用、粗体、斜体、删除线、链接、代码、分割线和 Markdown 图片。

Markdown 不开放任意 HTML。图片地址仅接受站内路径或 HTTP / HTTPS 地址，不允许 `javascript:`、`data:` 等不安全来源。

视频作为结构化媒体素材处理，不使用任意 HTML `<video>` 注入正文。产品媒体区域已经支持视频；如果以后需要正文视频块，应继续使用受控组件语法而不是开放原始 HTML。

## R2 媒体访问

R2 使用两种不同用途的访问方式：

```text
ASSETS_BUCKET Worker Binding
→ 后台上传、删除和校验媒体对象

R2 Custom Domain
→ 用户前端公开读取图片、GIF 和视频
```

管理员需要在 R2 Bucket 设置中手动连接媒体域名，例如：

```text
https://assets.example.com
```

随后在后台“站点设置”中录入同一个 Origin。数据库字段为：

```text
site_settings.media_base_url
```

数据库中的媒体记录只保存 `object_key`。公开媒体 URL 统一生成：

```text
{media_base_url}/{object_key}
```

生产环境不使用 `r2.dev`，也不在每条媒体记录中保存完整 URL。

## 简化管理登录

项目定位是个人或小团队，因此后台默认采用简单的单管理员密码登录，不把复杂账号和权限体系作为建设目标。

后台登录页只输入密码。Cloudflare Worker 手动绑定：

```text
ADMIN_PASSWORD
SESSION_SECRET
```

两项可以使用普通变量或 Secret，不限制字符长度。绑定值不写入 GitHub、D1 或 `wrangler.jsonc`。登录成功后使用签名安全 Cookie 维持短期会话。

现有登录仍应保留必要的基础安全措施，例如安全 Cookie、会话校验和登录限速，但不为个人或小团队场景增加额外的账号、角色和权限管理复杂度。

部署配置启用 `keep_vars`，重新部署时保留 Cloudflare Dashboard 中手动绑定的变量。

## 分区驱动模型

“分区管理”负责业务分区的名称、图标、排序和启用状态。

创建分区后，后台自动提供该分区的工作区：

```text
[分区名称]
├─ 产品管理
├─ 分类管理
├─ 标签管理
└─ 转化池
```

```text
/             English Storefront

/go/:code     转化跳转
```

本仓库只维护一个正式 Cloudflare Worker。

## 数据库规则

- 当前无业务数据，初始设计修正通过重建 D1 完成；
- 本次基线冻结后，表结构只能通过新的 `migrations/*.sql` 修改；
- PR 必须在全新的本地 D1 上完整执行所有 migration；
- `main` 部署前自动应用尚未执行的正式 D1 migration；
- 不允许在 Cloudflare Dashboard 中手工改表；
- 所有业务关系由外键和数据库约束保护；
- 所有可删除业务实体使用软删除与操作审计。
